# Instruções de implementação para IA

## Objetivo

Corrigir o alinhamento visual e responsivo das ações `Remover item` em arrays do FormView e adicionar uma ação explícita, acessível e segura para gerar/preencher UUID em campos de ID elegíveis, preservando o modelo de valores, paths, validação, semântica nativa e i18n.

## Referência

- Análise humana: `16_AN_20260926-013801.md`
- Branch: `feature/20260925163201-schema-form`
- Estado: Não iniciado
- Gate de entrada: G3 aprovado; handoff ao Developer para G4

## Restrições obrigatórias

- Não usar o atributo HTML técnico `id` para decidir se o campo é um campo de negócio ID.
- Aplicar a regra de elegibilidade documentada no AN e registrar qualquer decisão do HRS que a altere.
- Não sobrescrever valor existente sem confirmação explícita; cancelamento deve preservar valor e foco.
- Usar `crypto.randomUUID()` ou fallback RFC 4122 v4 baseado em `crypto.getRandomValues()`; nunca `Math.random()` ou `uid()` para gerar UUID de formulário.
- Manter inputs nativos, labels, paths canônicos, `aria-invalid`, `aria-describedby`, foco, teclado e fluxo de validação.
- Não criar dependência de rede, não expor UUID em logs desnecessários e não modificar o comportamento de identificadores internos da árvore.
- Não mascarar overflow com scroll horizontal global; o formulário deve continuar responsivo dentro do painel.
- Não finalizar, liberar, commit/push ou mesclar a branch neste ciclo.
